# Aloft: original specialized-cell generation

Research date: 9 November 2026. The original loaded program builds **312 small
specialized routines on 156 RAM pages**. A finite source model independently
predicts all **11,232 generated bytes**, then matches every byte in the retained
native pre-`$F02B` capture. It also predicts the final 144 template bytes, the
generator's self-modified group counter and all 256 bit-reversal lookup bytes.
All comparisons pass. No generated native byte is an input to those models.

This advances the distinct program previously observed as vertical ribbons.
It does not bind the separately requested moving three-layer scene, or prove
the final image produced by these routines. The [original-byte association](aloft-decoded-parts-20261109.md)
owns the compressed-source-to-loaded-generation link; the [earlier part study](aloft-parts-20261109.md)
owns wrapper localization and the separate 601-byte call-kernel expansion.

## Genuine source inputs and entry conditions

The source is complete logical generation 31 in the independently predicted
[ColorRAM-aware stream receipt](../../build/research/aloft-decode-20261109/color-analysis/accepted-01/color-stream-proof.json),
SHA-256 `44bbc6a94b22db33d81dc9f15178f1303a2db19fb22484292e0c6f894f00f4b2`.
Its full memory artifact is 65,536 bytes, SHA-256
`95a344b261b1b28d229da9778df80bae06eff39470ff4515820ce4e1fa86869e`.
The generator checker pins all six generation-state files and requires both
the known mask and physical-RAM payload mask to cover every source guard.
Unknown or device-only bits cannot supply code or constants.

The guarded original source domains are:

| Source span, half open | Role |
| --- | --- |
| `$F000..$F02B` | Initializer call order and clock-domain setup. |
| `$F43D..$F47C` | Preceding screen/state initialization. |
| `$F47C..$F55A` | Paired-page emission and the fixed boundary patch block. |
| `$F55A..$F626` | Mask injection/rotation and operand updates. |
| `$F626..$F64E` | Two twenty-byte operand tables. |
| `$F64E..$F787` | Later generators, bit reversal and disjoint store footprints. |
| `$F787..$F817` | Two original 72-byte cell templates. |

`$F47C` explicitly initializes the forward pointer to `$2000`, the mirrored
pointer to `$BB00`, and the four mask bytes through `$F5A8`. The original
`LDX` immediate at `$F5F0` is zero. Those are source literals/bytes, not
captured zero-page state or the later self-modified counter value. Previous
contents of the destination pages are unknown and never read by the model.

The operand update includes `ADC #$08`, so the model declares **decimal mode
clear** as an entry condition before prediction. After prediction, the genuine
native entry CPU flags independently confirm `D=0`; the pre-`$F02B` CPU flags
also have `D=0`. The preceding `$F43D` routine contains no `SED` at its
recognized instruction boundaries. Carry inputs needed by the mask and operand
macros are supplied by their own `LSR`, `SEC` or `CLC` instructions. This is a
conditional source calculation followed by entry-condition validation, not an
output-derived choice of CPU flags.

## Paired pages and the two templates

There are eighty emission iterations. For iteration `i=0..79`:

```text
forward page = $20 + i
mirror page  = $BB - i
```

Each iteration copies 72 template bytes to both pages. The source order is
`Y=71..0`, writing the forward destination and then the mirrored destination
at each Y. Forward-page bit 2 selects the template: clear selects `$F787`, set
selects `$F7CF`. Both members of each pair have the same variant.

The first routine on a page is **35 bytes** at offset `$00`; the second is
**37 bytes** at offset `$23`. The normal form contains `INC $D011`. The
row-end form instead contains `LDA #$18` / `STA $D011`, accounting for its
two extra bytes. The specialized operands perform OR/AND transforms on two
state bytes, select lookup entries, update stored state, and retain a final
`CMP ($00,X)` before `RTS`. The separate
[cell-semantics study](aloft-cell-semantics-20261109.md) owns execution
dataflow and read effects; this generator does not execute either routine.
The [primary VIC/CPU reading](aloft-cell-primary-20261109.md) separately
defines the actual-read-byte contract for `INC $D011`, including its raster-MSB
read bit and old-value dummy write. Generated opcode identity alone does not
establish a scroll-only increment or a raster-technique label.

The two destination sets overlap on pages `$6C..$6F`. In particular, later
iterations overwrite the earlier mirrored copies there. The model preserves
that source order instead of treating the two sets as independent outputs.
The distinct page union is `$20..$BB`: **156 pages**, each with 72 generated
bytes. The remaining 184 bytes of each page are outside the generated-cell
claim. An output memory file uses a separate 65,536-byte mask; its zero bytes
outside that mask are not predictions of native RAM.

The eighty paired copies account for 11,520 logical stores. The fixed patch
block adds forty more. Together these are **11,560 logical source-store
operations**, with 328 overwrites and 11,232 distinct final bytes. This is
source accounting, not a native executed-store trace or cycle measurement.

## Four mask phases and group operands

`$F55A` patches four mask values into both cells in both templates before each
copy. Its shifts and rotates produce this cycle:

| Phase | `$20` | `$21` | `$22` | `$23` |
| --- | --- | --- | --- | --- |
| 0 | `$FF` | `$C0` | `$80` | `$7F` |
| 1 | `$3F` | `$F0` | `$E0` | `$1F` |
| 2 | `$0F` | `$FC` | `$F8` | `$07` |
| 3 | `$03` | `$FF` | `$FE` | `$01` |

The next shift would clear `$20`, so the source resets the four bytes to phase
zero. After each four-page group, `$F5B9` advances the operand specialization:

- The previous second state operand becomes the first, and the second
  increases by eight. Template A begins with state addresses `$07/$0F`;
  template B begins with `$0F/$17` and reverses the lookup/store ordering.
- `$F63A + group` supplies the scratch-store zero-page operand.
- `$F626 + group`, ORed with `$80`, supplies the screen/state destination's
  low address byte. A negative table value switches its high byte from `$07`
  to `$00`; it is not an arbitrary constant high byte supplied by the model.

The original template supplies active group zero. Updates 1 through 19
prepare the remaining active groups. A final update to group 20 happens after
the last page copy; no generated page consumes it. Its scratch-table read is
at `$F64E`, which is also the first opcode of the following routine. That
source-known `$A9` byte is intentionally recorded as data in the final unused
template update. The model does not invent a twenty-first table entry or
silently skip this real source read. The final self-modified `$F5F0` value is
20, matching the native capture.

## Forty boundary patches

After the paired copies, `$F4C5..$F559` applies ten writes to each of pages
`$6C..$6F`. Six alter corresponding OR/AND operands in both cells:

| Page | First OR immediate, offsets `$03/$26` | First AND, `$05/$28` | Second AND, `$0C/$2F` |
| --- | --- | --- | --- |
| `$6C` | `$FF` | `$82` | `$01` |
| `$6D` | `$3F` | `$E8` | `$07` |
| `$6E` | `$3F` | `$E0` | `$17` |
| `$6F` | `$FF` | `$80` | `$41` |

The other four writes per page alter **opcodes**, not lookup high bytes:
offsets `$11/$34` change `$8D` to `$0C`, and offsets `$17/$3A` change `$85`
to `$04`. These are the store-to-NOP substitutions that suppress the normal
screen/state and scratch writes in the boundary variants. Their exact read
and bus behavior belongs to separate CPU-source analysis. This generator
proves the replacement bytes and suppressed stores; it does not claim that
every replacement performs a physical target read.

The checker uses a finite recognizer for this exact constant-store block:
`LDA #literal`, a list of absolute stores, then `RTS`. Its footprint and all
forty source PCs/values are retained in the generation ledger. It is not a
general opcode interpreter.

## Surrounding initialization cannot overwrite these cells

The source call order is `$F43D`, `$F47C`, `$F64E`, `$F686`, then a tail jump
to `$F676`. The strengthened source contract records the adjacent routines'
finite nominal store footprints:

| Routine | Store footprint relevant to the dependency check |
| --- | --- |
| `$F43D`, before cell generation | Screen addresses `$07C0..$07E7`, color destinations `$DBC0..$DBE7`, 32 state bytes `$07,$0F,..,$FF`, eight bytes `$0787 + 8*i`, and `$3FFF`. |
| `$F64E` | Twenty-five 25-byte copies at stride 24: `$0500..$0758`. |
| `$F686` | Four sets of 200 ten-byte copies at stride nine: `$C000..$C708`, `$C800..$CF08`, `$D000..$D708`, `$D800..$DF08`; its own template operands at `$F830+`, pointer bytes `$10/$11` and port `$01`. |
| `$F676` | `$0400..$04FF`. |

All of these footprints are disjoint from the 11,232 claimed cell bytes,
the cell templates `$F787..$F816`, and the group-counter operand `$F5F0`.
The predecessor's `$3FFF` write falls in page padding, outside the cell's
first 72 bytes. The footprint checker does not mistake the `$F8` immediate
operand of `AXS #$F8` for a `SED` instruction. It records actual recognized
instruction boundaries. These are static address-domain checks; they do not
claim native bus mapping, IRQ-interleaving coverage or a complete mutation log.

`$F676` constructs the `$0400` lookup by shifting eight fresh bits from each
index into the destination. Every old destination bit is discarded, so the
scalar result is `reverse_bits8(index)` for all 256 indices. No old lookup
byte, native or source-predicted, is needed as input. All 256 independent
results equal the later native lookup.
