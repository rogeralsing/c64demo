## Source-bound observation plan

Original B8 at $819D copies current shared sprite Y to all eight VIC Y
registers, then current pointer phase+32 to $43F8..$43FF. All those stores
precede JSR $E000 at $81F3, which advances the B9 motion coroutine. Current
VIC state must remain distinct from the next source pair written by B9.

Planned even consumer context has cursor899 ($E531/$ED01) and pair[14,16],
then next pair900 ($E532/$ED02)=[13,16]. Planned odd context has cursor942
($E55C/$ED2C)=[16,24], then next943 ($E55D/$ED2D)=[16,24]. These original
table entries are source facts, not filters on guessed visual geometry.
The actual stopped cursor, current state, coroutine generation and code
bytes will all be checked before a window is accepted.

Capture anchors are $819D before consumer, $81F3 after current Y/pointers,
$821C before hardware-Y/timer-latch setup, $8267 before LDA19/STA DC0F,
$826C immediately after that store, $8516 parity selector, $828C CIA1
handler entry and $8298 immediately after saved-SP TXS. Root also plans
a later any-PC line0 pair after each cutoff, keeping every watch active
through that pair and removing them only afterward;
that later RAM can already belong to a successor state. No same-field
completed-pixel claim follows from a filename or screenshot. Actual VIC
model/resource enums are bound; PAL launch does not assume a 6569 subtype.

Trace watches cover VIC $D000..$D3FF, CIA1 $DC00..$DC0F, CIA2 $DD00..$DD03,
both pointer tables $43F8..$43FF/$47F8..$47FF, plus reads of $D012/$D112
and calibration $DC04. All trace setup/delete generations and attached-r
contexts must remain. Load hooks provide observed post-step context, even
when IRQ dispatch changes PC; PC=instructionPC+length is not assumed.
The source-graph consumer owns independent execution/write reconstruction;
the hardware consumer owns new VIC draw-tail/framebuffer interpretation.

## Added readback windows and exact byte framing

The two original r-only windows retain partial RMW oracles. Root extends the
same naturally progressing native03 with even/odd readback windows at source
cursors975 ($E57D/$ED4D), pair[23,32], and1015 ($E5A5/$ED75), pair[26,40].
Each uses the same nine anchors and all eight watches; no reset or PC/RAM
patch is introduced. The exact second attached command is
`r; bank io; m d000 d03f; bank ram`. All four subcommands are read-only CPU
observations/bank selection, and the monitor RAM bank is restored last.
Source guards for monitor command separators and the actual help/probe
responses remain. Side effects stay off.

The 64 I/O bytes after each readback hook are **CPU-visible** values. Unused
and read-only bits are not a direct observation of all stored raw bits.
These records are comparison oracles only: neither the read-input stream
nor the typed source model receives them as predicted-state inputs. Direct
store A/X/Y and later full stored endpoints remain separate observations.

Ordinary probe186 contains 432 original bytes but re-encoding its Unicode
event response produces 512 bytes. The saved PETSCII column includes invalid
UTF8; original received bytes decoded as Latin1 therefore carry every trace
offset and hash. The frozen auditor still verifies the unchanged event
replacement decode. The bounded raw-parser diagnostic retains the original
response offsets, all four rows and CPU equality with following r187. Its
monitor-dot is $D040 while CPU PC is $828C: the prompt is not a CPU-PC oracle.

The exact pinned interrupt helper remains retained. Its new declared raw
adapter changes only byte framing/hashes, load-header counting, and the
