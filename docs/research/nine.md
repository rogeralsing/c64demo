# Nine: several display mechanisms behind one illusion

Linus Åkesson identifies [Nine](https://www.linusakesson.net/scene/nine/) as his
Fjälldata 2025 C64 demo. The release page was posted on 2 February 2025;
the [written explanation](https://www.linusakesson.net/scene/nine/explanation.php)
followed on 28 February. Both primary pages were inspected on 7 November 2026.
The original executable is now inspected in bounded CPU checks and native PAL
captures. Those follow-ups establish particular paths, rather than every
section of the production.

## What the author explains

Different sections use different mechanisms. When the rotating circle becomes
nearly flat, character graphics replace one digit. Fixed sprite priority makes
that switch necessary before the digits occupy exactly the same raster lines.

The upper-border section combines idle graphics, timed background-color changes
and crunched sprites. A one-time crunch makes supporting sprites span three
ordinary sprite heights; prepared pointer tables and `$D018` changes select
different data as their counters wrap. Copy-chunk tables depend on the moving
device's vertical position.

Stable DMA timing also constrains placement. Always-active sprites on both
sides of a moving sprite can keep the stolen-cycle interval constant. This
does not permit every hardware sprite to move freely. Three raster-code
variants handle horizontal alignment and the different VIC pixel-pipeline
delays. The listed `$70` invalid mode contributes to the idle-graphics masking;
it is not an extra hardware sprite.

These are attributed explanations, including short timed code excerpts.
They are not measurements from the downloaded executable.
[Primary technical article](https://www.linusakesson.net/scene/nine/explanation.php)

## Artifact and inspected paths

`research/nine/acquire.py` preserves the two author pages and original PRG under
ignored `build/research/nine/`, with byte counts, SHA-256 hashes and a decoded
load header in `acquisition.json`. No downloaded program is executed by that
script. The author's executable link is
[lft-nine.prg](https://hd0.linusakesson.net/files/lft-nine.prg).

The acquired PRG is **14,356 bytes**, SHA-256
`a257fa0436bc0d97fbeaa906c55489786a26ee6a9213aa3fd0d8e21f9612d839`.
Its load word is `$0801`; the BASIC stub is line 30, `SYS2061`, naming entry
`$080D`. The acquisition script only inspects file bytes; the separate native
lane follows normal startup through this entry.

The follow-ups keep their evidence scopes separate:

- [Binary analysis](nine-binary.md) checks the unpacker, relocation and all
  three generated timing families against independent host formulas.
- [Native initialization](nine-native.md) follows the original startup,
  captures actual character ROM, and matches the relocated/generated bytes.
- [Character replacement](nine-character-path.md) follows the scripted
  representation switch and checks one complete native 3×3 stamp against
  physical RAM and actual Color RAM.
- [Device tracing](nine-device.md) observes a naturally clipped call and a
  complete 21-row call, including pointer switches and temporary code patches.
- [Trident's ghostbyte article](ghostbyte-shine-through.md) supplies a separate
  documented construction and small teaching sources. They are not identified
  as Nine's implementation or Orbit Untold's complete scroller.

Complete independent pixel composition, the other native detector outcome,
physical VIC behavior and whole-production performance remain open. No complete
released source has been established.
