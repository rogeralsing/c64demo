# Smoking Fish: native NUFLI comparison

This continues the [source and format analysis](nufli.md) using the original
Smoking Fish NUF distributed in the pinned Mufflon 1.0 archive. The native
session is owned separately; the comparison script only reads saved files.
It launches no emulator and performs no CPU interpretation.

**Both stable native screenshots match all 64,000 decoded palette indices
exactly: 128,000 pixel comparisons, zero mismatches and zero unknown RGB
values.** The original loaded bytes, generated code and setup copies also
match. The corrected comparison and all failed-trial evidence are retained;
no original viewer or exporter colour-math defect was found.

The exact PRG is
`build/research/nufli/amigaconverts+samples/02-SMOKING_FISH.NUF.prg`,
23,042 bytes, SHA-256
`f44e6c1c3285683d2d73864e6d676e68539b77beb3e43daabd4a22adaa929093`.
Its payload loads at `$2000`; the author's documented start is
**SYS 12288 / JMP $3000**, with the normal KERNAL and I/O mapping retained.
This is the original PAL-only viewer, not Crossbow's later PAL/NTSC replacement.

## Capture points and exact byte checks

The natural `$3000` entry is checked against every byte of the original
`$2000..$79ff` payload. `$3109` is after the original generator and setup
copies, but before it reads the CIA interrupt latch and enables interrupts.
Its `$1000..$1f41` generated body is compared with the previously checked
original-generator output: **all 3,906 bytes**, without omissions.

The entire loaded range is also checked after generation, including the
generator's self-modified instructions and final template state. The separate
setup copies at `$0280..$02a7`, `$03f8..$03ff`, `$07f8..$07ff` and
`$7ff8..$7fff` are checked directly. The first two source/format research
receipts remain independent inputs to this comparison.

`$3110` is the first IRQ handler, reached once each displayed frame before
arming the nested line-42 handler. `$31e0` is immediately after the generated
body returns. A stable `$3110` screenshot retains the completed prior scan;
its live register state is the following frame's pre-display state, so it
must not be mistaken for all the registers that produced the saved pixels.
Actual raster/cycle/clock observations accompany each capture.

There is one explicit runtime code patch: `$31a7` writes the CIA2-derived
bank-selection byte at **`$19bc`**. Its upper six bits preserve the port state;
its low two bits select bank zero. At frame checkpoints the comparison records
that byte separately and compares all other 3,905 generated bytes exactly.
It does not silently mask an arbitrary code range. KERNAL/BASIC state, stack
contents and unspecified zero-page memory are outside the original picture's
byte oracle; they are not presented as a whole-RAM match with the offline CPU
harness.

Each native raw RAM dump is separately compared with **all 65,536 physical
RAM bytes in its same-stop VSF**. The audited VICE 3.10 `C64MEM` module v0.1
contains four port/cartridge prefix bytes, 65,536 RAM bytes and fifteen port
state suffix bytes; the slice is `[4:65540]` of its 65,555-byte payload.
This uses the pinned official `c64memsnapshot.c` writer schema, not a guessed
header skip or CPU-visible I/O bytes in place of underlying RAM.

## Pixel comparison contract

The reference is the source-derived 64,000-byte logical palette-index image,
not the original input BMP or its preview RGB palette. The decoder's bitmap,
normal sprite and two left-edge sprite layers are documented in
[the preceding note](nufli.md). Native agreement is a new check of that model;
the previous input-art comparison was never a lossless oracle.

The primary comparison uses this NUFLI viewer's screenshot coordinates:
**origin `(32,32)`, rectangle `(32,32)..(352,232)`**, exactly 320×200 pixels.
VICE 3.10's `vicii-timing.h` specifies 32-pixel normal left/right borders and
displayed raster lines 16..287. Its `vicii.c:177..187` passes that geometry to
the raster; `raster/raster.c:134..144,531..549` indexes and exposes the physical
raster framebuffer. `screenshot.c:157..159,119..121` maps PNG y to physical
framebuffer row`y+16`. There is no fine-scroll normalization in this crop.

An independent [origin proof](../../build/research/quondam/hardware-source/nufli-origin-proof.json)
compares **all 104,448 pixels in each entire PNG** against the corresponding
same-stop VSF framebuffer rows 16..287. Both match exactly. Without consulting
the decoded picture, the full framebuffer's nonblack bounds are
`(32,48)..(352,248)`, mapping to PNG`(32,32)..(352,232)`.

Both VIC snapshots show the vertical border already open at raster 41,
cycle 40 (`vborder=set_vborder=0`), with YSCROLL 0. The pinned `viciitypes.h:56`
sets first DMA line 48; `vicii-cycle.c:51..59,228..238` supplies the bad-line
and DEN-latch conditions. An open border therefore permits this image's
first fetch at 48, rather than imposing the ordinary border top at 51. The
viewer cycles`$D011=$38/$3a/$3c/$3e` and finishes with`$10`, changing RSEL
around the lower part of the frame. That is compatible with retaining an
open vertical border, but the exact bottom RSEL-store beam timing was not
measured here; no exact missed 247/251-comparator claim is made.

The first comparison incorrectly assumed that ordinary origin `(32,35)` and
reported **39,372 mismatches per screenshot**. The last three compared rows
were entirely black because that crop extended below the picture. This was a
comparison-harness origin error. Its full receipt, crops and difference images
remain in `native-analysis/standard-origin-trial/`; the final receipt pins
their hash and explicitly records the correction. The new fixed origin is
supported by the independent native image bounds and VIC state, rather than
chosen by an offset search that minimizes errors.

Native RGB values must match the session's explicit 16-colour palette exactly.
An unknown RGB value remains an error rather than being assigned its nearest
colour. Every differing pixel is retained as `(x,y,expected index,actual
index,actual RGB)`, with row/column histograms and separate totals for:

- x0..23: the FLI-bug repair region;
- x24..311: the six normal sprite underlays;
- x312..319: the rightmost region without a normal sprite.

The diagnostic crop and magenta difference image are saved beside the JSON.
The full 320×200 count remains primary; no line, corner or sprite edge is
excluded to make it pass. Pixels outside that rectangle are not in this image
oracle, so the comparison makes no claim about border rasterbars or the rest
of the PAL frame. Physical composite output and other VIC revisions are also
outside this capture's scope.

## Reproduction

After the separately owned session is closed and its monitor transcript,
same-stop RAM/VSF files and screenshots are saved:

```sh
rtk proxy python3 research/nufli/native_capture.py \
  --capture build/research/nufli/native-02 \
  --output build/research/nufli/native-analysis \
  --palette palettes/colodore.vpl
```

The script classifies RAM captures by their recorded natural PC and matches
screenshots/VSFs using the same PC and CPU clock. It requires an explicit
register observation before each capture and rejects an unclosed session.
The output is `native-comparison.json`, with original/analysis/input hashes,
exact-byte results and complete mismatch records.

## Completed native result

The successful `native-02` session loaded the unchanged picture at its embedded
address and reached `$3000` naturally through BASIC. It was closed after the
captures. The viewer was not entered by changing the PC, and its payload was
not patched.

| Natural checkpoint | CPU clock | Raster / zero-based cycle | Comparison |
|---|---:|---|---|
| `$3000` entry | 2,162,625 | 7 / 24 | All 23,040 loaded payload bytes exact |
| `$3109` post-generator | 2,294,553 | 229 / 30 | All 3,906 generated bytes, loaded range and setup copies exact |
| `$3110` stable A | 2,636,527 | 41 / 40 | All 64,000 pixels exact; all other generated bytes exact |
| `$3110` stable B | 2,734,807 | 41 / 40 | Same exact result; bitmap RGB identical to A |

The first pending `$3110` IRQ occurred at raster 230 after initialization and
is not a steady-frame image. The later screenshot stops are five PAL periods
apart: **98,280 cycles**, with identical raster/cycle positions. This measures
that captured interval, not an independent check of every intervening frame.

The sole runtime code byte `$19bc` is `$97` in both stable captures, versus
the generator's pre-IRQ `$03`: upper CIA2 port bits were preserved and low
bits 3 still select bank zero. All remaining 3,905 generated bytes match. Every
raw 64KB dump also matches all 65,536 same-stop VSF physical RAM bytes.

The pixel result includes all 4,800 left-edge repair pixels, all 57,600 normal
underlay-region pixels and all 1,600 rightmost pixels. No row, corner, sprite
edge, colour or unknown RGB value was masked. This confirms the independently
decoded image-plane and colour-switch model for this exact picture/viewer in
the captured VICE PAL model; it is not a physical-machine or NTSC result.
